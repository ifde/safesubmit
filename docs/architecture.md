# Архитектура SafeSubmit

SafeSubmit — сервис для выявления похожих научных работ и фиксации подтверждённых сведений об их происхождении.

## Основной поток

1. Пользователь загружает статью в SafeSubmit.
2. Оркестратор управляет обработкой и при наличии DOI запрашивает у Oracle API метаданные: автора, дату публикации и другие подтверждаемые сведения.
3. Сервис ML Embedding преобразует текст статьи в векторное представление с помощью BERT.
4. Сервис LSH Hash получает вектор и вычисляет LSH-бакеты — компактные признаки для поиска похожих документов.
5. Сервис Index Search ищет документы с пересекающимися LSH-бакетами во внутреннем индексе и возвращает кандидатов на совпадение.
6. Оркестратор записывает результат в смарт-контракт. Если найдено сходство, контракт публикует событие `SimilarityFlag` в реестре фактов.

## Компоненты

- **Оркестратор** — единая точка запуска процесса и координации сервисов.
- **Oracle API** — внешняя интеграция для подтверждения метаданных по DOI.
- **ML Embedding (BERT)** — выделяет смысловое представление текста.
- **LSH Hash** — превращает эмбеддинг в идентификаторы бакетов для быстрого поиска похожих работ.
- **Index Search** — хранит и проверяет внутренний индекс LSH-бакетов.
- **Блокчейн / смарт-контракт** — неизменяемо фиксирует сведения о документе и события о найденном сходстве.
- **Реестр фактов** — доступный для проверки журнал подтверждённых записей и `SimilarityFlag`.

## Взаимодействие

Внутри SafeSubmit оркестратор вызывает ML, LSH и индексный сервисы по gRPC. Внешние интеграции выполняются через API: Oracle API для метаданных и блокчейн для фиксации результатов.

Такая схема переносит ресурсоёмкую обработку текста вне блокчейна, а блокчейн играет роль источника правды, куда сохраняются данные после обработки.
