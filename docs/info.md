# Информация по поиску дублей

## Задача SafeSubmit

SafeSubmit получает новую статью и ищет в базе документов её возможный первоисточник. Сервис должен находить не только полные копии, но и перефразированные тексты с сохранённым смыслом.

## Роль корпуса

**Корпус** — это база исходных, проверенных документов. Она заранее обрабатывается: для каждого документа создаётся эмбеддинг и добавляется запись в индекс поиска.

Поток работы:

1. В корпус заранее загружаются исходные документы.
2. Пользователь загружает новую, возможно заимствованную статью.
3. SafeSubmit ищет наиболее похожие документы в корпусе и возвращает кандидатов на роль оригинала.

Корпус нужен, чтобы проверять реальную задачу сервиса: не просто сравнивать два заранее выбранных текста, а искать источник среди большой базы.

## Что измеряем

- **True Positive** — найден настоящий источник заимствования.
- **False Positive** — система ошибочно отметила другой документ как похожий.
- **False Negative** — система не нашла настоящий источник.

На их основе считаются Precision, Recall и F1-score. Индекс по корпусу используют сервисы LSH Hash и Index Search.

## Внешние benchmark-наборы

### PlagBench — основной benchmark

[PlagBench](https://github.com/Brit7777/plagbench) содержит три нужные категории: `verbatim`, `paraphrase` и `summary`. Полная версия включает 46,5 тыс. синтетических пар; публично доступен evaluation-набор. [Описание исследования](https://arxiv.org/abs/2406.16288).

### PAN 2025 — LLM-перефразирование

[PAN 2025 Generated Plagiarism Detection](https://pan.webis.de/clef25/pan25-web/generated-plagiarism-detection) содержит пары «подозрительный документ — источник» и разметку заимствованных фрагментов. Он нужен для независимой проверки на LLM-перефразированном плагиате.

### Machine-Paraphrased Plagiarism — проверка семантической модели

[Machine-Paraphrased Plagiarism](https://zenodo.org/records/4621403) содержит большой набор выровненных оригинальных и машинно перефразированных абзацев, включая тестовые данные из arXiv и диссертаций. Он позволяет отдельно проверить устойчивость модели к перефразированию.

## Пример из статьи про LSH, IPFS и блокчейн

Статья *Decentralised Plagiarism Detection System for Open Textual Educational Resources based on Blockchain Technology* использовала открытые научные статьи из Europe PMC API.

| Часть эксперимента | Как использована |
| --- | --- |
| 2 600 открытых статей | Общий исходный набор |
| 2 300 статей | Настройка LSH, построение базы MinHash-векторов и hash-band индекса |
| 300 статей | Тесты: по 100 кейсов direct, paraphrased и semantic plagiarism |

Для тестов авторы копировали или перефразировали фрагменты статей. Precision проверяли на исходных текстах без искусственно добавленного плагиата, а Recall — на созданных вариантах с заимствованиями.

### Ограничение описания эксперимента

Авторы не уточняют, находился ли источник каждого из 300 тестовых кейсов среди 2 300 индексированных статей или среди исходных версий тестовых статей. Поэтому нельзя утверждать, что все 100 источников каждого типа были взяты из корпуса из 2 300 документов.

Для SafeSubmit эксперимент должен быть строже: источник каждого заимствования заранее находится в корпусе, а изменённая статья подаётся в систему как новый запрос.
